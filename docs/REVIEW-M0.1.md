# M0.1 독립 검토 준비 자료

작성 기준: T-007 종료 시점. 이 문서는 작성자의 **자체 검토**다. 독립 검토를 대체하지 않는다.

## 1. 코드 경로 검토 결과

| 항목 | 확인 내용 | 결과 |
|---|---|---|
| 프로세스·네트워크 실행 | `src/`에 `subprocess`, `socket`, `urllib`, `http`, `ctypes`, `winreg`, `multiprocessing`, `asyncio`, `ssl` import 없음. `os.system/popen/startfile/exec*/spawn*` 호출 없음 | 없음 |
| 동적 코드와 동적 import | `eval`, `exec`, `compile`, `__import__`, `importlib`, `runpy`, `pickle` 없음 | 없음 |
| 파일 쓰기 | 쓰기 호출은 `jsonio.write_text_file` 하나뿐이고, `cli.cmd_handoff_create`에서 `--output`과 `--json-output` 값으로만 호출된다. `--force`일 때는 같은 디렉터리에 임시 파일 `.quota-handoff-*.tmp`를 만든 뒤 `os.replace`로 교체하며, 실패하면 지운다. 디렉터리는 만들지 않는다 | 사용자가 지정한 경로와 그 디렉터리의 임시 파일로 한정 |
| 파일 읽기 | `--fixture`, `--policy`, `--input`으로 지정한 정규 파일만 읽고 1 MiB로 제한한다. `--demo`는 파일을 읽지 않는다 | 한정 |
| 환경 정보 | 환경변수, 홈 디렉터리, 로그인 사용자 조회 없음. 현재 시각만 읽는다 | 없음 |
| 민감 입력의 출력 | 오류 메시지에 입력 값 원문을 넣지 않고 필드 경로만 쓴다. 필드 이름은 40자로 자른다. handoff 마스킹 경고는 경로와 종류만 출력한다. 단, handoff 본문은 사용자 입력을 마스킹한 뒤 그대로 출력한다(의도된 기능) | T-007에서 타임스탬프와 source 값 반복 출력 제거 |
| 경로 호환 | `pathlib`/`os.path`를 사용하고 줄바꿈은 LF로 고정한다. 같은 출력 경로 판정에 `realpath`와 `normcase`를 쓰므로 Windows에서는 대소문자를 구분하지 않는다. BOM이 있는 UTF-8도 읽는다 | Windows에서만 실행 확인. macOS/Linux는 미검증 |

T-007에서 고친 결함:
- 사용자명 없이 비밀번호만 있는 URL 자격 증명(콜론 바로 뒤에 비밀번호)이 마스킹되지 않았다.
- 일반 문장 속 `token=`/`password:` 표현이 오탐되었다.
- 오류 메시지에 잘못된 타임스탬프와 source 값 원문이 그대로 출력되었다.
- 출력 경로 비교가 Windows에서 대소문자 차이를 같은 파일로 인식하지 못했다. `--force`를 주면 Markdown 파일을 JSON으로 덮어쓸 수 있었다.

## 2. 테스트가 실제로 검증하는 범위

총 140개다. 기존 96개는 모두 유지했고, 그중 2개는 정책 결정(R1/R2)에 따라 기대값을 바꿨다. 새 테스트는 44개다.

| 영역 | 검증하는 것 | 검증하지 않는 것 |
|---|---|---|
| 정책 | 경계값 0/79/80/94/95/100, 신선도 300/301초, 미래 시각 60/61초, 등급 우선 선호, 부분 후보 처리, 창 상태, 입력 순서 순열 불변성 | 실제 공급자 데이터의 의미(필드 해석)는 M1 범위 |
| 정적 검사 | AST에서 직접 import와 직접 호출 | `getattr` 문자열 같은 간접 접근, 표준 라이브러리 내부 동작 |
| 런타임 차단 | Python 수준의 프로세스·소켓 진입점을 실패 함수로 바꾼 상태에서 CLI 실행 | 네이티브 코드, 패치하지 않은 진입점. 샌드박스가 아니라 회귀 신호다 |
| 마스킹 | 합성 문자열 기준으로 정해진 형식의 탐지와 오탐 방지 | 다른 비밀 형식. **마스킹은 보안 보장이 아님** |
| 공개 콘텐츠 | 프로젝트 전체 파일에서 홈 경로, 이메일, 비밀 패턴을 일반 규칙으로 검사 | 프로젝트 고유 비공개 용어는 공개 테스트에 목록으로 둘 수 없어 저장소 밖에서 별도 확인 |
| 플랫폼 | Windows, Python 3.14 로컬 실행 | CI 매트릭스(Linux/macOS, 3.11–3.13)는 아직 한 번도 실행하지 않음 |

## 4. 비차단 확인 요청 (결정 필요)

- **동점 처리:** "입력 순서" 대신 `(provider, account_label)` 정렬 순서를 쓴다. 원래 입력 순서를 쓰면 AT-05(순서를 섞어도 결과 동일)와 충돌하기 때문이다.
- **스키마 버전:** 창 `state` 필드를 선택 필드로 추가했지만 `schema_version`은 `0.1`로 유지했다. 기존 문서는 그대로 유효하다.
- **reason code 이름 변경(공개 전 인터페이스 변경):**
  - `preference_not_eligible`를 `preference_ignored_riskier_tier`, `preference_ignored_not_eligible`, `preference_ignored_provider_not_found`로 나눴다.
  - `no_candidate_with_confirmed_usage`를 `no_candidate_with_complete_usage`로 바꿨다.
  - `selected_has_unreported_windows`는 삭제했다.
- **부분 후보의 near_limit 처리:** 보고된 창 하나라도 95% 이상이면 누락 창이 있어도 `near_limit`으로 제외하고, 수동 검토 대상으로 두지 않는다.
- **콘솔 출력:** Windows 레거시 콘솔(cp949)에서는 코드페이지로 표현할 수 없는 문자가 `?`로 바뀔 수 있다. 파일 출력은 항상 UTF-8이다.

## 5. M1(실시간 읽기 전용 어댑터) 진입 조건

1. B1부터 B4까지 해소.
2. 어댑터를 실행할 호스트 또는 격리 VM의 사용 승인을 소유자에게서 별도로 받는다.
3. 대상 CLI의 읽기 전용 명령과 응답 스키마를 설치된 버전에서 격리 환경으로 확인한다. contract 테스트 fixture는 **합성 데이터 또는 식별자를 제거한 데이터**로만 만든다.
4. 설계 요건:
   - 실행 파일은 PATH 검색 없이 허용 목록에 있는 경로만 쓴다.
   - `shell=False`, 인자 허용 목록, 시간 제한, 출력 크기 제한을 둔다.
   - 응답의 계정 식별자는 파싱 직후 폐기한다.
   - 오류는 창 `failed`나 스냅샷 `error`/`unknown`으로 매핑한다.
   - 공급자가 제공하지 않는 창은 `unsupported`로 매핑한다.
   - 리셋 크레딧 같은 사용 유도 정보는 정규화하지 않는다.
5. 정적 테스트를 갱신한다. 프로세스 실행은 어댑터 모듈 한 곳에서만 허용하고, 코어(`normalizer`, `policy`, `handoff`, `report`)는 지금 규칙을 유지한다.
6. 실시간 소스는 명시적으로 opt-in해야만 쓴다. 기본값은 fixture/demo로 두고, 실패하면 `unknown`으로 처리하며 fixture 모드는 계속 동작해야 한다.
7. 공급자 약관과 정책을 검토해 사용량 조회 방식이 허용 범위인지 확인한다.
